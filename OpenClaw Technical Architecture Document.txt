Technical Architecture Document
OpenClaw Automated Intraday Options Trading Setup
Platform: Windows + Linux + OpenClaw + Zerodha + Telegram
Phase 2 Deliverable: Full Pipeline with OpenClaw Browser Automation & Simulation

1. Project Objective
Build an automated OpenClaw-based intraday options monitoring and dummy trade simulation
system for Zerodha. OpenClaw handles all browser automation (Chrome launch, login check,
navigation). The strategy engine runs a Python loop for ongoing session-based monitoring
and sends Telegram alerts for every event. All trades are simulated/dummy only.
The bot must never place, modify, cancel, square off, or confirm real broker orders.

2. Trading Strategy Definition
15 Minute Chart Direction Logic:
- 5 EMA crossing above 20 EMA -> Enable CE trades only
- 5 EMA crossing below 20 EMA -> Enable PE trades only
3 Minute Premium Confirmation Logic:
- Confirm EMA crossover on premium chart before trade signal
- Monitor ATM option dynamically
- Send simulated entry and exit alerts in Telegram

3. Phase 2 Deliverables

Deliverable 1 - setup.bat / setup.sh
- Check prerequisites (Python 3.8+, Node.js 22+, Chrome)
- Create Python virtual environment (venv/)
- Install Python dependencies (requests, psutil)
- Install OpenClaw globally via npm
- Configure OpenClaw gateway.mode=local (required for browser tools)
- Configure OpenClaw sandbox.mode=off (no sandbox runtime needed)
- Create the 'main' OpenClaw agent
- Create logs/ and prompts/ directories
- Prompt for Telegram bot token + chat_id -> config/telegram.json
- Generate default strategy prompt -> config/strategy_prompt.json
- Prompt for AI model provider + API key -> config/openclaw_model.json
- Create config/settings.json with simulation mode defaults
- Show validation summary

Deliverable 2 - run.bat / run.sh -> run_bot.ps1 / run_bot.sh -> runtime.py
- Activate Python virtual environment
- Add npm global bin to PATH (for openclaw command)
- Load config/settings.json
- Prepare strategy prompt from config/strategy_prompt.json
- Optionally load architecture reference document into prompt context
- Configure OpenClaw (API key as env var, agent identity, auth profile)
- Start OpenClaw gateway (background process for browser/tool WebSocket)
- Run OpenClaw agent:
  * OpenClaw opens Chrome (its own browser, not Playwright)
  * Navigates to kite.zerodha.com
  * Checks login state (dashboard vs login form)
  * Sends Telegram login reminders/confirmation
  * Reads strategy prompt and monitors market
- Once agent finishes -> start strategy engine loop:
  * Every 60s check session windows (09:30-11:30, 13:30-15:00)
  * Simulate 15m EMA direction -> CE/PE bias
  * Simulate 3m EMA crossover for entry
  * Track active positions with monitor cycles
  * Exit with target (20-50%), SL (0 to -10%), or hard SL (-10%)
  * Telegram alerts for every event
- On Ctrl+C: stop gateway, send Telegram shutdown alert

6. Key Design Decisions

6a. Chrome opened by OpenClaw, not Playwright
The Python runtime does NOT launch or control Chrome. OpenClaw's agent opens Chrome
using its own browser tool (via the gateway). The Python side only starts the gateway
and launches the agent with the strategy prompt.

6b. Terminal TTY inheritance
The OpenClaw agent subprocess inherits the real terminal (no stdout/stderr PIPE capture).
This means all OpenClaw output (thinking, tool calls, browser status) appears live in the
user's terminal instead of being captured silently.

6c. Gateway required
OpenClaw's browser/tool services require a WebSocket gateway (openclaw gateway run).
The runtime starts this as a background subprocess before launching the agent, and
kills it on shutdown.

6d. OpenClaw config (gateway + sandbox)
Two mandatory config settings that setup scripts enforce:
  - gateway.mode = local   (enables gateway for browser/tools)
  - agents.defaults.sandbox.mode = off  (no sandbox/Docker required)

6e. Lazy Telegram config load
telegram_manager.py loads config/telegram.json lazily (on first send_message call)
with try/except error handling, so a missing or invalid config does not crash the bot.

6f. OpenClaw Telegram outbox
OpenClaw does not receive Telegram credentials and must not call Telegram sendMessage
directly. When OpenClaw needs a user-facing status alert, it appends one line to
prompts/openclaw_telegram_outbox.txt. The Python runtime watches this outbox, sends
Telegram messages through telegram_manager.py, and suppresses repeated browser page
read / Chrome DevTools warnings for the current bot start.

6g. Browser-derived chart signals only
The Python strategy monitor does not create random dummy entries or exits. OpenClaw
must diagnose the browser charts and write prompts/chart_signal.json with the latest
NIFTY 15m bias, CE/PE premium states, entry/exit confirmation, prices, and timestamp.
Missing or stale chart_signal.json data is treated as waiting/no-entry.

7. Telegram Notification Events
- "Bot starting"
- "Bot stopped"
- "OpenClaw agent starting / completed / failed"

- "Zerodha login confirmed!"

- "Session limit reached: <Morning/Afternoon>"

- Entry/exit session status updates
- OpenClaw outbox status messages after Python dedupe/throttling
